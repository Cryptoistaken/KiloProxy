# NetShield for KiloProxy — Feasibility Study & Implementation Plan

**Status:** Research only (no code changes). Verified against the bundled engine sources
(`SocksVpnService.kt`, `Utility.kt`, `pdnsd.xml`, tun2socks + pdnsd C sources) and Proton's
NetShield implementation (`protonvpn-android-app` `NetShieldProtocol.kt`).

---

## 1. How KiloProxy's DNS machinery actually works (verified in code)

```
app DNS query (UDP :53 to 8.8.8.8)
   │  VpnService: addDnsServer("8.8.8.8") + addRoute("8.8.8.8/32")  [SocksVpnService.kt:568,577]
   ▼
tun interface
   │  tun2socks --dnsgw 10.10.10.1:8091  [SocksVpnService.kt:701-702]
   │  process_device_dns_packet() rewrites UDP:53 → 10.10.10.1:8091,
   │  remembers client (src port) in a connection table, rewrites replies back
   ▼
pdnsd (libpdnsd.so, spawned at start, 0.0.0.0:8091)  [SocksVpnService.kt:646-655]
   │  conf generated by Utility.makePdnsdConf() from R.string.pdnsd_conf  [Utility.kt:158]
   │  query_method=tcp_only; single server block: ip=<profile DNS>, port=dnsPort
   ▼
upstream DNS server (user's choice, via raw TCP :53 on the physical link —
   pdnsd runs under the app UID, which is disallowed from the tunnel)
```

Key facts:

- **DNS interception is a single choke point**: pdnsd on `0.0.0.0:8091`. Anything that
  responds on `10.10.10.1:8091` is transparently treated as "the DNS server" by tun2socks —
  the packet-rewrite table is keyed by the client's source port, not by the responder
  identity. This makes pdnsd the natural (and only) place to filter.
- **pdnsd is a full upstream validating cache**, not a dumb forwarder: it re-resolves via
  referrals, supports per-server include/exclude policies, `rr` records, `reject` lists.
- **The upstream DNS is reached OUTSIDE the tunnel** (app UID excluded). This matters for
  option B (see below): any public resolver promoted to "upstream" must be reachable from
  the raw ISP link.
- NetShield prefs exist and are only UI today: `PREF_NETSHIELD_ENABLED`,
  `PREF_NETSHIELD_BLOCK_ADULT` (`Constants.kt:51-52`), written by `NetShieldScreen.kt`,
  **never read by the engine**. `makePdnsdConf` has exactly one caller
  (`SocksVpnService.kt:639`), so changing its signature is cheap.

## 2. pdnsd's blocking capabilities (verified in bundled source, v1.2.9b-par)

Options that actually exist in the shipped `app/src/main/jni/pdnsd` build:

| Mechanism | Where | Behavior |
|---|---|---|
| `exclude = ".dom", ".sub.dom";` (server section) | conf-parser.c:1157 | Leading dot → the domain **and all subdomains**, case-insensitive; multiple `exclude=` lines accumulate (line 299 `exclude_list_add` → `C_EXCLUDED`) |
| `use_server()` first-match gate | dns_query.c:2886-2906 | Linear scan of the list per attempted resolution; `C_EXCLUDED` match → that server is not queried |
| No server left to answer | dns_query.c:3317 | `rc = RC_SERVFAIL; /* No server up */` → **client receives SERVFAIL** |
| `policy` default | docs | Default `included` → non-listed domains are queried exactly as today. Zero impact on unblocked traffic |

Verified `pdnsd.conf.5.in` semantics for `exclude`:
> "If the given name starts with a dot, the whole subdomain of the given name including the
> one of that name is matched". Names are case-insensitive; trailing dot optional.

Additional honest notes:

- Blocked answers (SERVFAIL) are **not cached** — no stale blocks, and list changes apply
  immediately on a reconnect with no cache purge. Cost: every blocked-domain query re-runs
  the linear scan (µs–ms range in C for ≤15k entries; fine on a phone).
- The config parser uses `getline()` (no line-length limit), but we still emit wrapped
  `exclude=` lines for readability/robustness.
- `rr { name=*.dom; a=0.0.0.0; }` sinkhole records exist but require parent NS/SOA records
  and ~2 sections per domain — impractical for thousands of domains. `reject`/`reject_policy`
  is IP-based, not name-based. So **the exclude list is THE native blocking primitive**.

## 3. Proton reference (read from `protonvpn-android-app`)

`net/typeblog/...` has no equivalent; Proton's `NetShieldProtocol.kt` is the model:

```kotlin
enum class NetShieldProtocol(val protocolString: String) {
    DISABLED(""),
    ENABLED("+f1"), ENABLED_EXTENDED("+f2"), ENABLED_EXTENDED_ADULT_CONTENT("+f3")
}
```

Proton implements NetShield **server-side**: the app sends a feature flag in the VPN
handshake and their VPN servers run the DNS filter. KiloProxy's endpoint is a bare SOCKS5
proxy with no server-side filter capability → **local DNS filtering is the only realistic
path**. Mode granularity maps onto KiloProxy the same way (off / base / base+adult).

## 4. Options, ranked

### Option A — pdnsd exclude-list blocking (RECOMMENDED, Phase 1)

Filter in the existing pdnsd config: add `exclude=` lines generated from bundled blocklist
assets. Blocked names → SERVFAIL → connections fail → ads/malware/trackers blocked.

**Fit:** highest. Zero new processes/binaries/ports; zero changes to tun2socks or the
tunnel; works on top of **whatever upstream DNS the user configured** (critical for the
app's CN/RU route-preset market, where foreign public resolvers are poisoned/blocked);
list is fully offline (no new network dependency); works for A/AAAA/any qtype; no DNS
leak changes (pdnsd's outbound path is untouched).

**Honest limits:** blocked answers are SERVFAIL, not NXDOMAIN (most apps show
"site not reachable"; some video players retry harder); list is static (stale over time);
second-stage CNAME targets resolved via referrals may not hit the exclude gate (verify on
device; residual leakage typical of DNS blockers using this mechanism).

### Option B — swap upstream to a blocking resolver (AdGuard DNS) — Phase 2 toggle

When NetShield is on, override the profile's DNS in `makePdnsdConf` with
`94.140.14.14` (ads+malware) or `94.140.14.15` (family/adult). ~5 lines of code.

**Fit:** low-effort but weakly suited to this app:
- pdnsd resolves upstream **outside the tunnel** over the RAW ISP link with
  `query_method=tcp_only` — AdGuard's TCP:53 must survive the ISP. In CN (GFW
  TCP-reset/poisoning) and RU (RKN resolver blocking) this can break ALL DNS, i.e. the
  app's core markets.
- Silently hijacks the user's explicitly configured DNS server.
- Blocklists are maintained server-side (the genuine advantage: freshness).

Verdict: keep as an optional later toggle ("cloud lists") for users who accept the
reachability trade-off; never the default.

### Option C — in-app UDP DNS responder (deferred)

Replace/spawn alongside pdnsd: a Kotlin `DatagramSocket` on `10.10.10.1:8091` that parses
queries, matches a bundled blocklist, answers blocked with NXDOMAIN/0.0.0.0 and forwards
the rest to the upstream. tun2socks's table makes it address-compatible with pdnsd.

**Fit:** most control (sinkhole answers, stats, per-domain policies) but the largest
surface: ~300–500 LOC DNS codec (label compression, EDNS0, question echo), new background
socket + lifecycle in the engine, malformed-packet hardening, concurrency, and more
CI-only verification pain. No benefit over A unless sinkhole answers or block stats become
required.

**Ranking: A ≫ B ≈ C, with B as a cheap phase-2 add-on and C only if sinkhole/stats are
demanded.**

## 5. Phase-1 implementation plan (Option A)

### 5.1 New assets (bundled blocklists)

| File | Content |
|---|---|
| `app/src/main/assets/netshield_blocklist.txt` | Ads+trackers+malware domains, one per line, `#` comments. Target 5–15k curated entries. |
| `app/src/main/assets/netshield_adult.txt` | Adult domains, 1–3k curated entries. |

Sources (with attribution headers committed in the files): AdGuard DNS filter
(`adguardteam.github.io/AdGuardSDNSFilter/Filters/filter.txt`, CC BY-SA 4.0) and
StevenBlack hosts (`StevenBlack/hosts`, MIT), reduced to bare domains:
strip `0.0.0.0`/`::` prefixes, drop comments/blank lines, lowercase, `sort -u`.
Avoid domains that also serve legit content (shareable CDN/API hostnames) to keep
false positives low.

### 5.2 Template — `app/src/main/res/values/pdnsd.xml`

Add a 5th format slot inside the existing server block (after `port = %d;`):

```
    uptest = none;
    exclude = %s;
```

`String.format` argument order becomes `(dir, dir, dns, port, excludeText)`.
Empty string → exactly one empty `exclude` line, which is harmless (no matches).

### 5.3 Asset → config generation — `app/src/main/java/net/typeblog/socks/util/Utility.kt`

- `fun parseBlocklist(raw: String): List<String>` — pure parser: drop comments/blank,
  lowercase, trim, skip entries with invalid characters (only `[a-z0-9.-]`). Unit-testable.
- `fun netshieldExclusions(context: Context): String` —
  reads `PREF_NETSHIELD_ENABLED` / `PREF_NETSHIELD_BLOCK_ADULT` via
  `PreferenceManager.getDefaultSharedPreferences(context)`; if disabled → `""`;
  otherwise loads `netshield_blocklist.txt` (`+ netshield_adult.txt` when adult on),
  dot-prefixes every entry (`.example.com` → blocks the domain AND subdomains, matching
  AdGuard/EasyList semantics), and renders wrapped lines, e.g. chunks of 100 per line:
  `\texclude = ".dom1", ".dom2", ...;`
- `makePdnsdConf(context, dns, port, exclusions: String = "")` — signature extension:
  pass the new value through to `String.format`. Default arg keeps any other caller safe
  (only one exists today: `SocksVpnService.kt:639`).

### 5.4 Engine hook — `app/src/main/java/net/typeblog/socks/SocksVpnService.kt`

In `start()` (the background connect thread), replace line 639:

```kotlin
Utility.makePdnsdConf(this, dns ?: "8.8.8.8", dnsPort, Utility.netshieldExclusions(this))
```

Modes take effect **at connect time** (pdnsd.conf is regenerated on every connect) —
the same UX as Proton (NetShield applies on reconnect). No intent extras, no
`Constants.kt`, AIDL, manifest, or UI changes.

### 5.5 Mode matrix

| NetShield | Block adult | pdnsd.conf effect |
|---|---|---|
| OFF | any | unchanged (current behavior) |
| ON | OFF | `exclude = <blocklist>` → blocked names SERVFAIL |
| ON | ON | `exclude = <blocklist + adultlist>` |

## 7. Risks & verification (CI-only environment)

1. **SERVFAIL semantics** — some apps ignore/hammer the resolver. The NetShield screen
   already warns "Some websites may not load properly when ads and trackers are blocked."
2. **False positives** — dot-prefix blocks the entry + all subdomains; mitigations:
   curated lists, blocklists that are already domain-level (AdGuard DNS filter).
3. **Reconnect required** for mode changes — document in UI later if desired.
4. **No local builds** — every change ships via `.github/workflows/build.yml`.
   On-device verification checklist after a CI build:
   - `dumpsys package com.kiloproxy.app` (install arm64 APK as per AGENTS.md)
   - connect with NetShield ON, then `adb shell` → inspect
     `/data/data/com.kiloproxy.app/files/pdnsd.conf` (run-as) shows the exclude lines
   - `nslookup doubleclick.net` (or `googleads.g.doubleclick.net`, `0.0.0.0`-listed
     domains) → SERVFAIL rcode
   - `nslookup example.com` → normal answer (non-blocked path untouched)
   - toggle adult → reconnect → adult entries present; toggle OFF → config back to stock
   - CN/RU regression: connect with `chn`/`ru` routes and custom DNS — no behavior change
     when NetShield off.
5. **Scale guardrails** — ≤15k base entries keeps config parse (<1 s at connect,
   once per connect) and per-query scan trivial; file size ~0.5–1.5 MB.
6. **Staleness** — list ships with the app; future work: optional fetch-on-connect toggle
   (would convert this into a hybrid A+B, reusing the same generation path).
7. Engine rule compliance: `Utility.kt`/`SocksVpnService.kt` get new functions and one
   call-site change only; no UI code is touched in `ui/` — satisfies the "engine never
   modified for UI" rule (this is a feature, not a UI pass) and the engine tab/tag
   snapshot convention should still be applied before landing (`pre-netshield` tag).
